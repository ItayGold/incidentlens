# Contributing

IncidentLens currently welcomes feedback and changes to public documentation,
accessibility, the static landing page, and synthetic incident examples.

## Safe contributions

Use entirely fictional data. Never submit production logs, customer details,
personal information, secrets, credentials, proprietary source mappings, or
private investigation implementation.

For a substantial change, open a GitHub issue describing the public workflow or
documentation problem first. State whether you are reporting current behavior
or proposing a future capability.

## Pull requests

Keep changes focused. Explain what changed and why. Check relative links and open
`public/index.html` locally when changing the page. Parse any modified JSON using
your preferred JSON validator.

Preserve the distinction between evidence and hypotheses in examples. Do not
turn design goals into shipped-feature, accuracy, privacy, or compliance claims.
Do not introduce external scripts, trackers, or dependencies without discussion.

## Security concerns

Follow [SECURITY.md](SECURITY.md). Do not publish sensitive details in a public
issue.

## Licensing

There is currently no license granting reuse or redistribution rights. Discuss
licensing with the repository owner before submitting material with third-party
licensing requirements. Only contribute material you have the right to submit.
